# Presentation roles and bounded revision

Use the user's chosen provider mapping; examples are configurable: economical GPT-6 Luna, balanced GPT-6 Sol, frontier GPT-6 Astra. No provider is required and no fixed price claim is made.

| Role | Task and boundary | Balanced profile |
|---|---|---|
| Presentation coordinator | Intake, storyboard, integration, versions and final output decision | Balanced, medium |
| Scientific storyteller | Audience-appropriate narrative, slide text and speaker notes from verified evidence | Balanced, medium/high for complex interpretation |
| Scientific verifier | Independent central claims, statistics, citations, figure meaning and limitations | Balanced, high; frontier for unresolved central validity risks |
| Figure/layout specialist | Visual directions, verified institutional/group branding, shared style, representative slides and data-faithful editable visuals | Balanced, medium |
| Export engineer | Reproducible PPTX/PDF or Beamer build, font/tool compatibility | Balanced, medium; deterministic checks in code |
| Visual reviewer | Rendered sample and final slides; branding/style consistency, readability, overlap, accessibility and cross-format agreement | Balanced vision-capable model, medium; actual image access required |
| Timing/copy editor | Notes, transitions, duration estimates and language; no independent empirical timing claims | Economical, medium |

Maximum four active agents including coordinator by default. Activate only necessary roles; avoid sending the full thesis to every worker. Reviewer contexts receive sources and frozen slide versions without desired verdicts. Context separation is not file access isolation.

Use economical models for bounded formatting and metadata tasks, not a cheaper incapable model for visual inspection. Escalate a specific unsolved scientific/technical issue, rather than upgrading every slide. Reuse verified evidence and revise only affected slides/dependencies. Keep checks even under an economy profile; reduce needless reruns and output length.

Each review issue has ID, slide/version, evidence or rendered location, severity, impact, correction, owner and verification. Writers cannot self-close scientific issues. Default three rounds; two rounds without progress stop with open issues. Stage-specific states: intake, storyboard, visual_design, representative_slides, draft, rendered, review, correction, final or blocked. Record the style and sample check status in the same run; sample checks are not full-deck verification. File export and scientific/visual verification are separate states.
